## 页面和交互

- 顶栏：门店名、预算输入、小报、单价设置、后台入口；超预算提示。
- 食材货架：7 类共 70 种食材，分类切换、名称/英文 ID 搜索、常点食材；SVG 卡通食材由代码绘制。
- 盆与清单：逐份加入、逐份移除、清空、图形盆/列表切换；同种食材最多 9 份。图形盆最多绘制 18 份，其余显示数量，计算不受此显示上限影响。
- 推荐：省钱狂魔、均衡打工人、减脂轻盈、放纵一顿；按分类计划、标签偏好及随机扰动抽选；“照着夹”替换当前清单。
- 称重：分组重量/价格、合计、热量、预算、份数、20 位角色评分及台词；支持返回修改、重开。
- 管理：`/admin` 路由、登录、食材、小报、账号、门店设置的前端页面。账号页在前端按 owner 角色限制；服务端是否强制鉴权未验证。

## 计算与状态

默认：店名“楼下那家麻辣烫”；19.8 元/斤；预算 25 元；荤素分价关闭。分价表为素菜 19.8、荤菜 26.8、丸滑 24.8、主食 19.8 元/斤。

```
重量(g) = 每份克重 × 份数
金额(元) = 重量 / 500 × 对应元/斤单价
热量(kcal) = 重量 / 100 × 每100g热量
角色评分 = round(clamp(50 + 55 × Σ(角色权重 × 归一化特征), 5, 99))
```

角色特征包括蔬菜占比、蛋白占比、碳水、加工食品、放纵食物、热量、价格、密度、辣度和颜色种类。特殊情况优先匹配预置台词，否则按分数段随机抽台词。这是本地规则和随机数，不是远端大模型生成；台词与评分仅代表游戏规则。

预算存于 `malatang.budget`，玩家设置存于 `malatang.settings`。初始清单为空，默认中辣。选菜数据没有发现持久化分支，刷新会重置清单。

## 接口与后端缺口

前端使用相对路径、JSON 请求和 same-origin 凭据；单次请求有 4 秒 AbortController 超时。以下是静态引用，不代表服务端已存在或可成功调用。

| 路径 | 前端方法/用途 |
|---|---|
| `/api/bootstrap` | GET：食材、小报、门店设置 |
| `/api/auth/me` | GET：当前登录身份 |
| `/api/auth/login` | POST：账号密码登录 |
| `/api/auth/logout` | POST：退出 |
| `/api/auth/password` | POST：当前密码和新密码 |
| `/api/admin/ingredients`、`/:id` | GET/POST/PATCH/DELETE：食材维护 |
| `/api/admin/news`、`/:id` | GET/POST/PATCH/DELETE：小报维护 |
| `/api/admin/accounts`、`/:id` | GET/POST/DELETE：账号维护 |
| `/api/admin/settings` | PATCH：门店设置 |

采集时真实 GET `/api/bootstrap` 返回首页 HTML，浏览器初始化解析失败后使用内置数据。仅确认这一路由当时行为，不能推断所有后台路径、其他域名服务或历史部署均无后端。未尝试默认口令登录原站，未发送远端管理写请求。

本地预览的 `server.mjs` 提供静态资源、`/admin` 页面入口，并对 `/api/*` 返回明确 JSON 503，让原有离线流程工作。它不是恢复出的服务器程序。
