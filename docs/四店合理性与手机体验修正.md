# 四店合理性与手机体验修正

2026-11-04，已上线 https://malatang.oneplums.cn/ 。版本 `20261104T014034Z`，上一版 `20261104T004029Z` 保留。

## 已发现并修正

| 小店 | 原有问题 | 当前表现 |
| --- | --- | --- |
| 奶茶 | 杯型和冰量区别不足，小料统一画成圆点；摇匀与奶盖的状态不够清楚 | 500/700mL杯型有尺寸区别，无冰/少冰/正常冰为0/2/5块；珍珠、椰果、布丁、芋泥等保留各自形状；鲜奶和燕麦奶摇匀后融合，奶盖保留上层；饮用时液面、小料随之减少 |
| 火锅 | 卡片遮住汤面；结算把没有捞出的菜也当成可吃食材 | 食材直接放在汤面，编号与下方火候对应；捞入碗后才能端碗开吃；捞早了可回锅继续煮，保留原时长且不重复扣币 |
| 早餐 | 加料时仍显示锅，成品丢失配菜与酱料；两种饼底差别不明显 | 制作在煎锅，加料移到餐盘；煎饼与手抓饼有不同纹理，鸡蛋、切好的配菜、酱料保留到包好的成品；咬痕同时裁掉饼与配菜 |
| 麻辣烫 | 碗本身空着，食材像菜单排在碗外；付款与评价顺序不顺 | 付款后直接在碗里点食材吃，每次最多盛六样，后续自动接上；先看账单并开吃，再看角色评价；“已享用”改为准确的“已下单” |

四家共用原有深棕线条、暖奶油色、食材图标与表情。没有加入另一套拟真图片。保持每日100金币、累计消费会员和未完成订单退款规则；回锅和吃喝不重复扣币。

手机底栏补充选配方、选汤底、挑食材/配菜的入口；火锅锅内清空时底栏可直接端碗开吃。按钮和碗内点击范围兼顾小屏，保留安全区与底部留白。默认静音及减少动态效果设置继续生效。

## 验证

- 30项规则/金币/用餐单元测试通过，包括新增未捞食材不能直接吃、回锅保留份数与烹煮时长。
- 320、375、390、430、768、1280、844像素宽度共35组五店完整流程通过，包含手机横屏；无页面横向溢出。
- 手机/桌面8组专项流程通过：奶盖、大杯、正常冰、三种不同小料；手抓饼加蛋/三种配菜/辣酱并咬食；六份满锅、捞早回锅、盛碗；七样麻辣烫依次享用。
- 正式域名手机/桌面共10组五店基础回归与8组四店专项回归通过。每日赠币去重、并发装扮购买、退款、刷新找回、余额不足、旧钱包迁移及受限存储回归通过。
- 用餐快速连点、设置持久化、默认静音、减少动效、键盘操作测试通过。实际查看了制作与成品截图及开发技能客户端截图；界面机械检测无问题。
- 52个静态文件SHA-256验证后原子切换，HTTPS与既有regex站点为200，未增加服务器服务。

手机验证采用Chrome手机尺寸视口，未进行物理手机测试。现有本地账本仍不支持跨设备同步。

## 实现

`src/games/kitchen-art.js` 提供杯、早餐、汤锅与熟制配菜；`dining.js` 提供前后层碗体、碗内食材与接续盛装；`rules.js` 支持火锅回锅并限制未捞菜进入餐桌；各店页面、手机快捷栏与麻辣烫结算同步接入。样式集中在 `public/assets/kitchen-refinements.css`。
