# 烧烤精修与通用金币闭环

日期：2026-11-03。已部署 https://malatang.oneplums.cn/ ，当前静态版本 `20261103T105249Z`。

## 本次完成范围

本轮先精修烧烤搭子，其他小游戏接入同一金币账本。奶茶/火锅/早餐的进一步动作和配方细节可按后续反馈分别精修，本轮未宣称三者也完成同级视觉精修。

### 烧烤

- 每串单独呈现正/反面火候与当前受热面，点击翻面有动作及文字反馈。
- 不同面显示相应的受热色泽和烤痕，烤过头有焦色与烟；减少动态效果设置下保留静态状态提示。
- 增加保温区与回炉。不同熟成时间的食材可以先后烤好，夹出后火候不再增加，解决原来整盘同时受热难以全部达标的问题。
- 选调味和实际撒料分开；实际点击后才产生撒料颗粒/蜜汁效果并计入口味分，暂停时不能撒料。
- 出炉有独立餐盘、逐串双面评价，并根据本局夹生/烤焦/漏撒料/口味/超预算给出具体点评。
- 手机底栏提供看烤炉、暂停后恢复、直接出炉；烤制中收起不能操作的食材架，减少无效滚动。

### 金币获取

- 首次使用本机账本：80枚见面礼。
- 完成有效游戏且达到50分：50–69分8枚、70–84分12枚、85–99分18枚、100分24枚。
- 各游戏每日首次合格结算加20枚，日期按当前浏览器本地日期计算。
- 烧烤至少烤制6秒且有食材；奶茶完成摇匀；火锅至少捞起一份；早餐完整完成3单后按班次平均分计奖并将基础奖励翻倍；麻辣烫至少3种食材、100g并称重。
- 未达标会解释原因，没有金币支出也可以继续所有基本玩法。

### 金币消费

装扮铺入口 `/#shop`。免费默认装扮保留；可购买夜市招牌70枚、薄荷/蜜桃主题各120枚、金边餐盘160枚、暖铜烤炉200枚。购买后自动换上，已购装扮可反复切换，不再扣币；余额不足禁止扣款。主题影响小馆配色，招牌显示在首页/店头，烤炉换色，金边餐盘用于出炉和结算。

装扮铺有分类筛选、始终可见的价格、手机余额栏和最近收支。账本仅保存在当前浏览器，不支持跨设备/账号同步；清除网站数据会清空金币与装扮。该本地游戏账本不包含充值、提现或真实货币功能。

## 账本正确性

每局使用唯一runId。结算页重渲染或同一麻辣烫账单重新打开不会重复发放；每日首过按游戏及日期去重；同一永久装扮不会重复扣费。现代浏览器通过Web Locks将同源多标签写入串行化，同时监听storage事件刷新余额。无Web Locks时退化为当前页面串行写入，不声称该退化分支可保证所有跨标签并发。

localStorage不可读写时保留本次会话的钱包并明确提示不持久化，不让游戏崩溃。收支流水超过200条会合并早期收支，仍保持流水合计与余额一致。最高分和原麻辣烫设置的既有存储键保留。

- `src/games/wallet-store.js`：持久化、并发写入、标签同步和会话降级。
- `src/games/wallet-ui.js`：金币入口、结算回执、装扮铺、皮肤挂载。
- `src/games/bbq.js`、`rules.js`：烧烤精修和保温/撒料规则。
- `src/games/common.js`：局编号、通用奖励接入、访问装扮铺时保护进行中的游戏。
- `src/app.js`、`src/checkout-ui.js`：麻辣烫称重奖励与同局去重。
- `public/assets/economy-bbq.css`：保持现有卡通画风的精修与钱包布局。
- `tests/economy.test.mjs`：账本/奖励/消费/幂等/余额守恒。
