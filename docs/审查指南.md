# 饭搭子代码审查指南

主站为 https://fandazi.oneplums.cn/ 。当前工作树和 CI 验证不代表已部署，实际版本以部署记录为准。审查对象是前端、游戏模型、本地存储、手机交互与静态构建；原管理后端未恢复。

## 复现起点

Node.js22.12+，执行 `npm ci`、`npm test`、`npm run build:static -- --out-parent ./work`。以本次命令实际报告的测试数量与通过状态为准。开发服务用 `npm start`，正式产物用 README 中的 Vite preview 命令；二者都应检查。路由为 `#home`、`#malatang`、`#bbq`、`#tea`、`#hotpot`、`#breakfast`、`#shop`、`#receipt`。

## 仓库内浏览器回归

```sh
npx playwright install chromium
npm run test:browser
```

`tests/browser/serve.mjs` 仅清理自己的 `work/browser-tests/`，然后构建根路径生产包与 `/play/` 测试包，启动 127.0.0.1:4186。不要在该端口预先启动其他服务。测试覆盖真实首页推荐、按推荐价格付费、制作与逐口享用、PNG 文件签名、文档刷新后小票及余额不变；另对五店生产包检查无 `window.advanceTime` 和 `window.render_game_to_text`，并检查静态资源请求。弹层测试核验背景 inert、Tab/Escape、焦点恢复、嵌套隔离与原属性恢复。

测试包允许 `--test-tools` 加速制作时间，生产包必须关闭这些钩子。测试不会修改线上存档或联系线上服务。失败时查看 `test-results/` 的 trace；CI 会保留失败 trace 七天。浏览器自动验证仅证明本地 Chromium 结果，不能替代微信或实体机验收。

## 产品约束

五店消费者视角，不做闯关、强制订单、每日任务和通关奖励。每天100金币，不付真实款；消费增长会员，取消未完成用餐退款并撤回相应成长。画风使用原SVG/角色素材，手机直接点食物操作，避免增加确认与复杂文字。

## 优先检查

1. 价格和资金：推荐金额是否等于实际消费，赠币是否同日去重，快速点击/多标签页是否重复扣费，未完成离开/重载退款是否正确。
2. 享用与存储：食物点击当下记录一口，动画约680ms后更新画面；重复输入阻断、最后一口后小票、动画中离开/刷新、存储不可用、其他标签页同步是否一致。享用不再收费。
3. 推荐与小票：三位搭子、不同预算/余额/口味带入有效菜单；火锅推荐需点击标价按钮才下锅；每家店小票显示实际金额、可下载PNG，真正刷新文档后最近小票仍可读。
4. 手机：320/375/390/430宽、短屏和横屏；分类横滑、底部安全区、推荐抽屉/结算滚动锁、焦点恢复、44px目标与拖动不误点；减少动态效果和关闭动效时可直接吃。
5. 域名迁移：origin/source/nonce匹配、旧数据保留、新站有消费时拒绝覆盖、迁移后重新加载偏好。两个真实域名才能完整验证跨域，localhost无法替代。
6. 构建与部署：按店懒加载的哈希JS/CSS、静态资源路径、无玩家bootstrap请求、HTML校验更新、哈希资源长缓存且历史哈希保留；不要把主动503的管理API当成玩家加载依赖。
